## 1. 概念总览

### 1.1 什么是截断

截断（Truncation）是指将一个**宽类型**的值存入**窄类型**时，超出目标类型表示范围的**高位数据被丢弃**，仅保留低位部分的行为。

```
以 uint16_t → uint8_t 为例（16 位 → 8 位）：

  原始值:  0x1234  (二进制: 0001 0010 0011 0100)
               ↓ 截断：丢弃高 8 位
  结果:    0x34    (二进制:         0011 0100)
```

### 1.2 截断 vs 回绕 vs 溢出

|概念|触发场景|行为|标准定义|
|---|---|---|---|
|**截断**|宽类型 → 窄类型赋值/转换|丢弃高位字节|无符号：定义良好；有符号：实现定义|
|**回绕**|无符号整数运算超出范围|对 2^N 取模|✅ 定义良好|
|**溢出**|有符号整数运算超出范围|不可预测|⚠️ 未定义行为|

```c
// 截断：宽赋给窄
uint16_t wide = 0x1234;
uint8_t narrow = wide;       // narrow = 0x34（丢弃高 8 位）

// 回绕：无符号运算超出范围
uint8_t a = 255;
a = a + 1;                   // a = 0（256 mod 256 = 0）

// 溢出：有符号运算超出范围
int8_t s = 127;
s = s + 1;                   // ⚠️ 未定义行为！
```

### 1.3 截断的数学本质

无符号整数截断在数学上严格等价于**对 2^M 取模**（M 为目标类型的位宽），这是 C 标准明确规定的行为。有符号整数截断在补码机器上表现为保留低位位模式并按目标类型重新解释，其具体结果属于实现定义行为：

```
无符号截断（标准定义）：
  0x1234 mod 256 = 0x34 = 52          ← 与位截断一致

有符号截断（补码机器上的实现定义行为）：
  (int16_t)0xFF00 = -256
  截断为 int8_t：保留低 8 位 0x00 = 0  ← -256 mod 256 = 0

  (int16_t)0xFF01 = -255
  截断为 int8_t：保留低 8 位 0x01 = 1  ← -255 mod 256 = 1
```

## 2. C 标准原文与解读

### 2.1 无符号整数截断

C17/C23 标准 §6.3.1.3p2 规定：

> _"Otherwise, if the new type is unsigned, the value is converted by repeatedly adding or subtracting one more than the maximum value that can be represented in the new type until the value is in the range of the new type."_

翻译：

> 否则（值无法在新类型中表示），如果新类型是无符号的，则通过反复加上或减去"新类型能表示的最大值加一"，直到值落在新类型的范围内。

**解读**：这等价于 `result = value mod (MAX + 1) = value mod 2^M`，是**定义良好**的行为。

### 2.2 有符号整数截断

C17/C23 标准 §6.3.1.3p3 规定：

> _"Otherwise, the new type is signed and the value cannot be represented in it; either the result is implementation-defined or an implementation-defined signal is raised."_

翻译：

> 否则，新类型是有符号的且值无法在其中表示；结果要么是**实现定义的**，要么触发一个实现定义的信号。

**解读**：有符号截断**不是未定义行为**，但结果**依赖编译器/平台**。在补码机器上，主流编译器（GCC、Clang、MSVC）的行为一致：保留低位位模式并按目标类型重新解释。

### 2.3 浮点转整数

C17/C23 标准 §6.3.1.4p1 规定：

> _"When a finite value of real floating type is converted to an integer type other than `_Bool`, the fractional part is discarded (i.e., the value is truncated toward zero). If the value of the integral part cannot be represented by the integer type, the behavior is undefined."_

翻译：

> 当有限的实浮点类型值转换为 `_Bool` 以外的整数类型时，小数部分被丢弃（即值向零截断）。如果整数部分的值无法由该整数类型表示，则行为是**未定义的**。

## 3. 位级原理

### 3.1 硬件层面

内存以字节为最小寻址单位。当宽类型数据存入窄类型的内存位置时，CPU 只写入**低地址端的 M 个字节**（小端序），或等效地只保留**最低 M 位的位模式**。

```
uint32_t 在内存中的布局（小端序）：

  地址:  [0]  [1]  [2]  [3]
  值:   0x78  0x56  0x34  0x12    → 0x12345678

截断为 uint8_t：只取地址 [0] 的字节
  结果: 0x78
```

### 3.2 通用截断公式

```
截断结果 = 原始值的位模式 & ((1 << M) - 1)

其中 M = 目标类型的位宽

示例：
  0x12345678 截断为 8 位：0x12345678 & 0xFF = 0x78
  0x12345678 截断为 16 位：0x12345678 & 0xFFFF = 0x5678
```

### 3.3 有符号数的截断

有符号数截断时，保留的低位位模式会被**按目标类型的符号性重新解释**。在补码机器上，主流编译器的行为等同于先对 2^M 取模，再映射到目标类型的有符号范围：

```c
// 正数截断：通常无害
int32_t  a = 0x0000017F;  // 383
int8_t   b = a;            // 0x7F = 127（在 int8_t 范围内，值不变）

int32_t  c = 0x00000180;  // 384
int8_t   d = c;            // 0x80 = -128（超出 int8_t 正数范围，变为负数）

// 负数截断：补码位模式的低位被保留
int32_t  e = -1;           // 补码: 0xFFFFFFFF
int8_t   f = e;            // 保留低 8 位: 0xFF = -1（值恰好不变）

int32_t  g = -256;         // 补码: 0xFFFFFF00
int8_t   h = g;            // 保留低 8 位: 0x00 = 0（值改变！）

int32_t  i = -257;         // 补码: 0xFFFFFEFF
int8_t   j = i;            // 保留低 8 位: 0xFF = -1（值改变！）
```

> 有符号截断属于**实现定义行为**——编译器必须文档化其行为，但不同编译器可能给出不同结果。在实际的补码机器上，GCC、Clang、MSVC 的行为一致，等同于上述位截断。

## 4. 整数截断

### 4.1 赋值截断

最常见的截断场景：将宽类型赋值给窄类型变量。

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // uint16_t → uint8_t（无符号，定义良好）
    uint16_t a = 0x1234;
    uint8_t b = a;
    printf("b = 0x%02X\n", b);           // 0x34

    // uint32_t → uint16_t
    uint32_t c = 0x12345678;
    uint16_t d = c;
    printf("d = 0x%04X\n", d);           // 0x5678

    // uint64_t → uint32_t
    uint64_t e = 0x123456789ABCDEF0ULL;
    uint32_t f = e;
    printf("f = 0x%08X\n", f);           // 0x9ABCDEF0

    // int → char（最常见的"意外"截断）
    int big = 300;
    char ch = big;
    printf("ch = %d\n", ch);             // 300 % 256 = 44

    // int → short
    int val = 40000;
    short sh = val;
    printf("sh = %d\n", sh);             // 40000 - 65536 = -25536

    return 0;
}
```

### 4.2 强制转换截断

通过强制类型转换显式截断，效果与赋值截断相同，但语义更明确：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 提取 32 位整数的各个字节
    uint32_t val = 0xDEADBEEF;

    uint8_t byte0 = (uint8_t)(val);       // 0xEF（最低字节）
    uint8_t byte1 = (uint8_t)(val >> 8);  // 0xBE
    uint8_t byte2 = (uint8_t)(val >> 16); // 0xAD
    uint8_t byte3 = (uint8_t)(val >> 24); // 0xDE

    printf("byte0 = 0x%02X\n", byte0);
    printf("byte1 = 0x%02X\n", byte1);
    printf("byte2 = 0x%02X\n", byte2);
    printf("byte3 = 0x%02X\n", byte3);

    // 提取低 16 位
    uint16_t low16 = (uint16_t)val;       // 0xBEEF
    printf("low16 = 0x%04X\n", low16);

    return 0;
}
```

### 4.3 符号性改变导致的"值变"

截断不仅丢弃高位，还可能因为**符号性改变**导致同一位模式被解释为不同的值：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 无符号 → 有符号（位模式不变，解释改变）
    uint8_t u = 200;          // 0xC8
    int8_t s = (int8_t)u;    // 0xC8 解释为有符号 = -56
    printf("unsigned: %u → signed: %d\n", u, s);

    // 有符号 → 无符号（位模式不变，解释改变）
    int8_t neg = -56;         // 0xC8
    uint8_t pos = (uint8_t)neg;  // 0xC8 解释为无符号 = 200
    printf("signed: %d → unsigned: %u\n", neg, pos);

    // 宽有符号 → 窄无符号
    int16_t neg16 = -1;       // 0xFFFF
    uint8_t u8 = (uint8_t)neg16;  // 0xFF = 255
    printf("int16_t(-1) → uint8_t: %u\n", u8);

    // 宽无符号 → 窄有符号
    uint16_t big = 300;       // 0x012C
    int8_t small = (int8_t)big;   // 0x2C = 44（恰好在 int8_t 正数范围内）
    printf("uint16_t(300) → int8_t: %d\n", small);

    uint16_t big2 = 400;      // 0x0190
    int8_t small2 = (int8_t)big2; // 0x90 = -112（超出 int8_t 正数范围）
    printf("uint16_t(400) → int8_t: %d\n", small2);

    return 0;
}
```

### 4.4 多级截断的连锁效应

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint64_t big = 0x0102030405060708ULL;

    // 逐级截断
    uint32_t a = (uint32_t)big;    // 0x05060708
    uint16_t b = (uint16_t)a;      // 0x0708
    uint8_t  c = (uint8_t)b;       // 0x08

    printf("a = 0x%08X\n", a);
    printf("b = 0x%04X\n", b);
    printf("c = 0x%02X\n", c);

    // 结论：无论经过多少级截断，最终结果等同于
    // 直接从原始值取最低 M 位
    uint8_t direct = (uint8_t)big;  // 0x08，与 c 相同
    printf("direct = 0x%02X\n", direct);

    return 0;
}
```

## 5. 浮点截断

### 5.1 浮点 → 整数：小数部分丢弃

浮点数转换为整数时，**小数部分被直接丢弃**（向零取整），这不是四舍五入：

```c
#include <stdio.h>

int main(void) {
    // 正数：向零取整（等同于 floor）
    double a = 3.99;
    int i = (int)a;
    printf("3.99 → %d\n", i);       // 3（不是 4！）

    // 负数：向零取整（等同于 ceil，不是 floor！）
    double b = -3.99;
    int j = (int)b;
    printf("-3.99 → %d\n", j);      // -3（不是 -4！）

    // 对比不同的取整方式
    double x = 3.7;
    printf("(int)x       = %d\n", (int)x);          // 3（向零）
    printf("(int)(x+0.5) = %d\n", (int)(x + 0.5));  // 4（四舍五入，仅正数正确）

    double y = -3.7;
    printf("(int)y       = %d\n", (int)y);          // -3（向零）
    printf("(int)(y-0.5) = %d\n", (int)(y - 0.5));  // -4（四舍五入，仅负数正确）

    return 0;
}
```

#### 正确的四舍五入方法

```c
#include <stdio.h>
#include <math.h>

int round_double(double x) {
    return (int)round(x);  // 使用 math.h 的 round()，处理正负数均正确
}

// 或手动实现（不依赖 math.h）：
int round_manual(double x) {
    return (int)(x + (x >= 0 ? 0.5 : -0.5));
}

int main(void) {
    printf("round(3.5)  = %d\n", round_double(3.5));   // 4
    printf("round(-3.5) = %d\n", round_double(-3.5));  // -4
    printf("round(3.4)  = %d\n", round_double(3.4));   // 3
    printf("round(-3.4) = %d\n", round_double(-3.4));  // -3
    return 0;
}
```

### 5.2 浮点 → 整数：精度丢失

即使值在目标类型范围内，浮点数的有限精度也可能导致截断后的值与"直觉"不同：

```c
#include <stdio.h>

int main(void) {
    // float 精度约 7 位十进制有效数字
    float f = 16777217.0f;  // 2^24 + 1，超出 float 精确表示范围
    int i = (int)f;
    printf("16777217.0f → %d\n", i);  // 16777216（丢失了 +1）

    // double 精度约 15~17 位十进制有效数字
    double d = 9007199254740993.0;  // 2^53 + 1
    long long ll = (long long)d;
    printf("2^53+1 → %lld\n", ll);  // 9007199254740992（丢失了 +1）

    // 大浮点数转整数：整数精度不足以表示
    double big = 1e18 + 1;  // 1000000000000000001
    long long lb = (long long)big;
    printf("1e18+1 → %lld\n", lb);  // 1000000000000000000（丢失了 +1）

    return 0;
}
```

### 5.3 浮点 → 整数：超出范围（UB）

浮点值超出目标整数类型的表示范围时，结果是**未定义行为**：

```c
#include <stdio.h>
#include <limits.h>
#include <math.h>

int main(void) {
    // 超出 int 范围
    double d = 1e20;
    int i = (int)d;       // ⚠️ UB！

    // inf 转整数
    float inf = INFINITY;
    int j = (int)inf;     // ⚠️ UB！

    // NaN 转整数
    double nan = NAN;
    int k = (int)nan;     // ⚠️ UB！

    // 安全做法：转换前检查范围
    double val = 42.7;
    if (val > (double)INT_MIN - 1 && val < (double)INT_MAX + 1) {
        int safe = (int)val;
        printf("safe = %d\n", safe);
    }

    return 0;
}
```

### 5.4 宽浮点 → 窄浮点

```c
#include <stdio.h>

int main(void) {
    // double → float：精度从 ~15 位降到 ~7 位
    double d = 3.141592653589793;
    float f = (float)d;
    printf("double: %.15f\n", d);  // 3.141592653589793
    printf("float:  %.15f\n", f);  // 3.141592741012573（精度丢失）

    // long double → double：精度损失取决于平台
    // x86: long double = 80 位扩展精度 → double 丢失约 3 位十进制
    // ARM: long double = double（无损失）
    long double ld = 3.14159265358979323846L;
    double d2 = (double)ld;
    printf("long double: %.20Lf\n", ld);
    printf("double:      %.20f\n", d2);

    return 0;
}
```

## 6. 函数参数传递中的截断

### 6.1 可变参数函数

调用 `printf` 等可变参数函数时，`...` 之后的参数会经历**默认参数提升**，但不会发生截断。然而，如果传入的类型与格式符不匹配，`printf` 内部会按格式符期望的类型"截取"参数：

```c
#include <stdio.h>

int main(void) {
    long long big = 0x100000042LL;

    // ⚠️ 用 %d 输出 long long：printf 只取 4 字节
    printf("%d\n", big);
    // 实际输出取决于调用约定和字节序
    // 小端序 x86-64：取低 4 字节 0x00000042 = 66
    // 但这是未定义行为！

    // 正确做法：使用匹配的格式符
    printf("%lld\n", big);  // 4294967362

    return 0;
}
```

### 6.2 窄类型参数的提升

`char`、`short` 等窄类型传给可变参数函数时，会被**整型提升**为 `int`，不会截断：

```c
#include <stdio.h>

int main(void) {
    unsigned char c = 200;

    // c 被提升为 int（值为 200），%d 期望 int → 匹配
    printf("%d\n", c);     // 200（正确）

    // 但如果格式符不匹配：
    printf("%hhd\n", c);   // 200（%hhd 告诉 printf 按 signed char 解释）
                            // 但实际传入的是 int（200），行为依赖实现

    return 0;
}
```

## 7. 截断的正面应用

截断不仅是"意外丢失数据"的代名词，更是**位操作的核心工具**。

### 7.1 提取字节

从多字节整数中提取单个字节是网络编程、文件解析的基础操作：

```c
#include <stdio.h>
#include <stdint.h>

// 从 32 位整数中提取 4 个字节（大端序）
void extract_bytes(uint32_t val, uint8_t bytes[4]) {
    bytes[0] = (uint8_t)(val >> 24);  // 最高字节
    bytes[1] = (uint8_t)(val >> 16);
    bytes[2] = (uint8_t)(val >> 8);
    bytes[3] = (uint8_t)(val);        // 最低字节（截断！）
}

// 网络协议解析：从字节流中提取 16 位字段
uint16_t read_u16(const uint8_t *data) {
    return ((uint16_t)data[0] << 8) | (uint16_t)data[1];
}

int main(void) {
    uint32_t ip = 0xC0A80001;  // 192.168.0.1
    uint8_t bytes[4];
    extract_bytes(ip, bytes);
    printf("IP: %u.%u.%u.%u\n", bytes[0], bytes[1], bytes[2], bytes[3]);
    // 输出: 192.168.0.1

    return 0;
}
```

### 7.2 位掩码操作

截断等效于**与掩码做位与**，是提取特定位字段的标准方法：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 从 32 位寄存器值中提取特定位域
    uint32_t reg = 0xA5B7C9D1;

    // 提取低 8 位（等效于截断为 uint8_t）
    uint8_t low8 = reg & 0xFF;
    printf("low 8 bits: 0x%02X\n", low8);        // 0xD1

    // 提取中间 8 位（先右移，再截断）
    uint8_t mid8 = (reg >> 8) & 0xFF;
    printf("mid 8 bits: 0x%02X\n", mid8);        // 0xC9

    // 提取低 12 位
    uint16_t low12 = reg & 0xFFF;
    printf("low 12 bits: 0x%03X\n", low12);      // 0x9D1

    // 提取 bit 4~7（4 位字段）
    uint8_t field = (reg >> 4) & 0xF;
    printf("bit 4~7: 0x%X\n", field);            // 0xD

    return 0;
}
```

### 7.3 环形缓冲区索引

截断可以替代取模运算，实现高效的环形索引（当缓冲区大小为 2 的幂次时）：

```c
#include <stdio.h>
#include <stdint.h>

#define BUF_SIZE 16  // 2^4
#define BUF_MASK (BUF_SIZE - 1)  // 0x0F

int main(void) {
    // 利用截断实现环形索引
    for (uint32_t i = 0; i < 20; i++) {
        uint8_t index = (uint8_t)(i & BUF_MASK);  // 截断为低 4 位
        printf("i=%2u → index=%2u\n", i, index);
    }
    // 输出: 0,1,2,...,15,0,1,2,3
    // 等效于 i % 16，但位与运算更快

    return 0;
}
```

### 7.4 颜色通道提取

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 32 位 ARGB 颜色值
    uint32_t color = 0xFF804020;  // A=255, R=128, G=64, B=32

    uint8_t a = (uint8_t)(color >> 24);  // 截断提取 Alpha
    uint8_t r = (uint8_t)(color >> 16);  // 截断提取 Red
    uint8_t g = (uint8_t)(color >> 8);   // 截断提取 Green
    uint8_t b = (uint8_t)(color);        // 截断提取 Blue

    printf("A=%u R=%u G=%u B=%u\n", a, r, g, b);
    // 输出: A=255 R=128 G=64 B=32

    return 0;
}
```

## 8. 截断导致的陷阱

### 8.1 循环计数器溢出

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 用 uint8_t 做循环计数器
    uint8_t count = 0;
    for (int i = 0; i < 300; i++) {
        count++;  // 超过 255 后回绕为 0
    }
    printf("count = %u（期望 300）\n", count);  // 输出: 44（300 % 256）

    // 用 uint16_t 存储大数组的长度
    size_t array_size = 70000;
    uint16_t len = array_size;  // 截断！
    printf("len = %u（期望 70000）\n", len);  // 输出: 4464（70000 % 65536）

    return 0;
}
```

### 8.2 计算中间结果被截断

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 计算两个 uint16_t 的平均值
    uint16_t a = 60000, b = 60000;

    // ❌ 错误：a + b 在 int 中计算（32 位），但赋值给 uint16_t 时截断
    uint16_t avg = (a + b) / 2;
    printf("avg = %u（期望 60000）\n", avg);  // 输出: 60000（恰好正确）

    // 但如果 a + b 超过 uint16_t 范围：
    uint16_t c = 50000, d = 50000;
    uint16_t avg2 = (c + d) / 2;
    printf("avg2 = %u（期望 50000）\n", avg2);  // 输出: 50000（正确）

    // 注意：c + d 先提升为 int（100000），除以 2（50000），
    // 赋值给 uint16_t 时 50000 在范围内，不截断。
    // 但如果先截断再除：
    uint16_t sum = c + d;  // 100000 截断为 uint16_t = 34464
    uint16_t avg3 = sum / 2;
    printf("avg3 = %u（期望 50000）\n", avg3);  // 输出: 17232（错误！）

    return 0;
}
```

### 8.3 符号扩展 vs 零扩展

截断后赋值给更宽的类型时，**符号扩展**和**零扩展**会产生截然不同的结果：

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 有符号窄类型 → 宽类型：符号扩展（高位填充符号位）
    int8_t neg = -1;          // 0xFF
    int32_t wide_neg = neg;   // 0xFFFFFFFF = -1（符号扩展）
    printf("int8_t(-1) → int32_t: %d (0x%08X)\n", wide_neg, wide_neg);

    // 无符号窄类型 → 宽类型：零扩展（高位填 0）
    uint8_t pos = 255;        // 0xFF
    uint32_t wide_pos = pos;  // 0x000000FF = 255（零扩展）
    printf("uint8_t(255) → uint32_t: %u (0x%08X)\n", wide_pos, wide_pos);

    // 混合场景：无符号窄 → 有符号宽
    uint8_t u = 200;          // 0xC8
    int32_t w = u;            // 0x000000C8 = 200（零扩展）
    printf("uint8_t(200) → int32_t: %d\n", w);

    // 混合场景：有符号窄 → 无符号宽
    int8_t s = -56;           // 0xC8
    uint32_t uw = s;          // 先符号扩展为 int32_t（0xFFFFFFC8）
                               // 再转为 uint32_t = 4294967240
    printf("int8_t(-56) → uint32_t: %u (0x%08X)\n", uw, uw);

    return 0;
}
```

> ⚠️ 这里的符号扩展/零扩展是**整型提升和类型转换**的行为，不是截断。截断只发生在宽→窄的方向。但这个对比很重要，因为实际代码中经常同时涉及两个方向的转换。

### 8.4 `char` 符号性导致的跨平台差异

`char` 的符号性由编译器/平台决定，这会影响截断后的符号扩展行为：

```c
#include <stdio.h>

int main(void) {
    char c = 200;  // 位模式: 0xC8

    // x86 GCC 默认 char = signed char：c = -56
    //   提升为 int 时符号扩展：0xFFFFFFC8 = -56
    // ARM GCC 默认 char = unsigned char：c = 200
    //   提升为 int 时零扩展：0x000000C8 = 200

    int i = c;  // 值依赖平台！
    printf("char(200) → int: %d\n", i);

    // 安全做法：显式指定符号性
    signed char sc = (signed char)200;    // 确定是 -56
    unsigned char uc = (unsigned char)200; // 确定是 200
    printf("signed char:   %d\n", sc);
    printf("unsigned char: %d\n", uc);

    return 0;
}
```

> 关于 `char` 符号性的详细讨论，参见《C 语言数据类型转换完全参考手册》第 2.1 节。

### 8.5 位域（Bit-field）截断

```c
#include <stdio.h>
#include <stdint.h>

// 位域结构体
// 注意：标准 C 仅允许 unsigned int、signed int、_Bool 作为位域类型
// 此处使用 unsigned int 以确保可移植性
struct flags {
    unsigned int a : 3;   // 3 位，范围 0~7
    unsigned int b : 5;   // 5 位，范围 0~31
    unsigned int c : 8;   // 8 位，范围 0~255
};

int main(void) {
    struct flags f;

    f.a = 10;  // 10 = 0b1010，但只有 3 位 → 截断为 0b010 = 2
    f.b = 50;  // 50 = 0b110010，但只有 5 位 → 截断为 0b10010 = 18
    f.c = 300; // 300 = 0b100101100，但只有 8 位 → 截断为 0b00101100 = 44

    printf("a = %u（期望 10，实际截断）\n", f.a);  // 2
    printf("b = %u（期望 50，实际截断）\n", f.b);  // 18
    printf("c = %u（期望 300，实际截断）\n", f.c);  // 44

    return 0;
}
```

> C 标准规定位域存储的位模式是**实现定义的**。对于无符号位域，赋值时超出位域宽度的值会被截断（标准 C 仅允许 `unsigned int`、`signed int`、`_Bool` 三种位域类型）。在补码机器上，无符号位域的截断行为通常等同于丢弃超出位宽的位，但不应假设所有平台都如此。

### 9.3 UBSan 与截断

截断本身是**实现定义行为**（有符号）或**定义良好行为**（无符号），不是未定义行为，因此 UBSan 不会直接报告截断。但 UBSan 可以检测与截断相关的其他问题：

```bash
# 检测有符号整数溢出（截断前的运算可能已 UB）
gcc -fsanitize=signed-integer-overflow main.c

# 检测浮点到整数的转换溢出
gcc -fsanitize=float-cast-overflow main.c

# 检测隐式符号转换（有符号 ↔ 无符号）
gcc -fsanitize=implicit-conversion main.c
```

## 10. 速查表

### 截断行为速查

|源类型|目标类型|行为|值是否改变|
|---|---|---|---|
|`uint32_t`|`uint16_t`|取低 16 位|值 > 65535 时改变|
|`uint32_t`|`uint8_t`|取低 8 位|值 > 255 时改变|
|`int32_t`|`int16_t`|取低 16 位，重新解释符号|值超出 -32768~32767 时改变|
|`int32_t`|`uint16_t`|取低 16 位，重新解释为无符号|通常改变|
|`double`|`int`|丢弃小数部分（向零取整）|有小数时改变|
|`double`|`float`|精度从 ~15 位降到 ~7 位|通常改变|
|`long double`|`double`|精度降低（平台相关）|通常改变|
|`int`|`char`|取低 8 位|值超出 -128~127 或 0~255 时改变|

### 截断公式速查

|操作|等效公式|
|---|---|
|截断为 N 位无符号|`result = value & ((1U << N) - 1)`|
|提取第 K 字节|`byte = (value >> (K * 8)) & 0xFF`|
|提取低 N 位|`result = value & ((1 << N) - 1)`|
|提取 bit M~N|`result = (value >> M) & ((1 << (N-M+1)) - 1)`|

### 安全截断检查模式

```c
// 整数截断前检查值是否在目标范围内
int will_truncate_int32_to_int16(int32_t val) {
    return val < INT16_MIN || val > INT16_MAX;
}

int will_truncate_int32_to_uint16(int32_t val) {
    return val < 0 || val > UINT16_MAX;
}

// 浮点转整数前检查
int will_truncate_double_to_int(double val) {
    return isnan(val) || isinf(val)
        || val <= (double)INT_MIN - 1
        || val >= (double)INT_MAX + 1;
}
```

### 截断口诀

> **宽赋窄，高位丢；位模式，原样留。**  
> **无符号，零扩展；有符号，符号凑。**  
> **浮转整，小数走；超范围，UB 有。**  
> **要提取，用掩码；位操作，截断够。**
