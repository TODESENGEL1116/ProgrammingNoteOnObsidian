## 1. 概念总览

### 1.1 什么是回绕

回绕（Wrap-around）是指无符号整数运算结果**超出表示范围**时，自动对 2^N 取模（N 为位宽），使结果"绕回"到有效范围内的行为。

```
数值轴（以 uint8_t 为例，范围 0~255）：

  ... → 253 → 254 → 255 → 0 → 1 → 2 → ...
                         ↑         ↑
                      上溢回绕    正常递增

  ... → 2 → 1 → 0 → 255 → 254 → 253 → ...
                ↑           ↑
             下溢回绕      正常递减
```

> C23 标准明确定义：回绕是"将一个值按 2^N 取模，其中 N 是结果类型的宽度。"

### 1.2 回绕 vs 截断 vs 溢出

|概念|定义|适用类型|行为|
|---|---|---|---|
|**回绕**|运算结果超出范围，对 2^N 取模|无符号整数|✅ 定义良好|
|**截断**|宽类型赋值给窄类型，高位丢弃|所有整数|实现定义|
|**溢出**|有符号运算结果超出范围|有符号整数|⚠️ 未定义行为|

```c
// 回绕：无符号运算结果超出范围
uint8_t a = 255;
a = a + 1;       // 回绕：256 % 256 = 0

// 截断：宽类型赋给窄类型
uint16_t wide = 300;  // 0x012C
uint8_t narrow = wide; // 截断：取低 8 位 = 0x2C = 44

// 溢出：有符号运算结果超出范围（UB！）
int8_t s = 127;
s = s + 1;       // ⚠️ 未定义行为！不是回绕！
```

> **关键区分**：回绕只发生在**无符号整数运算**中。有符号整数溢出是未定义行为，虽然多数硬件实际上也会"回绕"，但**绝不能依赖这一行为**。

### 1.3 数学本质：模算术

无符号整数运算在数学上构成一个 **2^N 元循环群（模 2^N 的环）**：

```
运算规则：result = (精确数学结果) mod 2^N

加法：(a + b) mod 2^N
减法：(a - b) mod 2^N  =  (a - b + 2^N) mod 2^N
乘法：(a × b) mod 2^N
```

```c
// 以 uint8_t（N=8, 模 256）为例：
// 加法回绕
(uint8_t)(200 + 100) = 300 mod 256 = 44

// 减法回绕
(uint8_t)(0 - 1) = -1 mod 256 = 255

// 乘法回绕
(uint8_t)(20 * 20) = 400 mod 256 = 144
```

## 2. C 标准原文与解读

### 2.1 标准条文

C17/C23 标准 §6.2.5p9 规定：

> _"A computation involving unsigned operands can never overflow, because a result that cannot be represented by the resulting unsigned integer type is reduced modulo the number that is one greater than the largest value that can be represented by the resulting type."_

翻译：

> 涉及无符号操作数的计算**永远不会溢出**，因为无法由目标无符号整数类型表示的结果，会被对"该类型能表示的最大值加一"取模而缩小。

### 2.2 逐句解读

|原文关键词|含义|
|---|---|
|"can never overflow"|无符号运算不存在"溢出"概念——标准不认为这是错误|
|"reduced modulo"|结果自动取模，不需要程序员手动处理|
|"one greater than the largest value"|模数 = MAX + 1 = 2^N|

### 2.3 对编程的影响

- **可以安全依赖**：无符号回绕行为在所有符合标准的 C 编译器上都一致
- **不等于"不会出错"**：回绕虽然是定义良好的，但如果你的业务逻辑不期望回绕发生，它仍然是一个 bug
- **CERT C 规范 INT30-C** 明确要求：确保无符号整数运算不会发生意外回绕

## 3. 回绕的位级原理

### 3.1 硬件层面

CPU 的 ALU 执行加法时，会产生一个**进位标志（Carry Flag, CF）**。对于 N 位无符号运算：

```
  1111 1111    (255)
+ 0000 0001    (  1)
──────────
1 0000 0000    (256，需要 9 位表示)
  ↑
  进位 CF=1，但只保留低 8 位 → 0000 0000 = 0
```

CPU 天然只保留低 N 位，高位的进位被丢弃——这就是回绕的硬件本质。

### 3.2 各运算的回绕演示

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 加法回绕
    uint8_t a = 200, b = 100;
    printf("200 + 100 = %u (mod 256)\n", a + b);  // 44

    // 减法回绕
    uint8_t c = 0, d = 1;
    printf("0 - 1 = %u (mod 256)\n", c - d);      // 255

    // 乘法回绕
    uint8_t e = 20, f = 20;
    printf("20 * 20 = %u (mod 256)\n", e * f);     // 144

    // 注意：运算过程中先提升为 int，再截断回 uint8_t
    // a + b 的实际过程：
    //   1) a、b 提升为 int：200 + 100 = 300（int 范围内，无溢出）
    //   2) 赋值给 uint8_t 时截断：300 % 256 = 44
    uint8_t sum = a + b;
    printf("sum = %u\n", sum);  // 44

    return 0;
}
```

> ⚠️ 注意：`uint8_t` 参与运算时会先被**整型提升**为 `int`，运算在 `int` 上完成（不会溢出），最后赋值回 `uint8_t` 时才发生截断。真正的"无符号回绕"发生在**结果类型本身就是无符号类型**且运算直接在该类型上完成时（如 `uint32_t` 在 32 位平台上的运算）。

## 4. 回绕的正面应用

回绕不仅是"不会崩溃"的保障，更是一种**强大的编程工具**。

### 4.1 环形缓冲区（Ring Buffer）

环形缓冲区是回绕最经典的应用场景。读写指针到达数组末尾时，通过回绕自动回到开头：

```c
#include <stdio.h>
#include <stdint.h>
#include <string.h>
#include <assert.h>

#define BUF_SIZE 8  // 2 的幂次，便于位运算优化

typedef struct {
    uint8_t data[BUF_SIZE];
    size_t head;  // 读指针
    size_t tail;  // 写指针
    size_t count; // 当前元素数
} ring_buf_t;

void rb_init(ring_buf_t *rb) {
    rb->head = 0;
    rb->tail = 0;
    rb->count = 0;
}

// 写入一个字节
int rb_put(ring_buf_t *rb, uint8_t byte) {
    if (rb->count == BUF_SIZE) return -1;  // 满
    rb->data[rb->tail] = byte;
    rb->tail = (rb->tail + 1) % BUF_SIZE;  // 回绕！
    rb->count++;
    return 0;
}

// 读出一个字节
int rb_get(ring_buf_t *rb, uint8_t *byte) {
    if (rb->count == 0) return -1;  // 空
    *byte = rb->data[rb->head];
    rb->head = (rb->head + 1) % BUF_SIZE;  // 回绕！
    rb->count--;
    return 0;
}

int main(void) {
    ring_buf_t rb;
    rb_init(&rb);

    // 写入 10 个字节（超过缓冲区大小 8）
    for (uint8_t i = 0; i < 10; i++) {
        if (rb_put(&rb, i + 'A') == 0)
            printf("put: %c\n", i + 'A');
        else
            printf("put: %c → 缓冲区满，拒绝\n", i + 'A');
    }

    // 读出所有字节
    uint8_t val;
    printf("读取顺序: ");
    while (rb_get(&rb, &val) == 0) {
        printf("%c ", val);
    }
    printf("\n");

    return 0;
}
```

#### 2 的幂次优化

当缓冲区大小为 2 的幂次时，取模运算可替换为**位与运算**，效率提升一个数量级：

```c
// 通用写法（慢）
index = (index + 1) % BUF_SIZE;

// 2 的幂次优化（快）——BUF_SIZE 必须是 2^n
index = (index + 1) & (BUF_SIZE - 1);

// 原理：
// BUF_SIZE = 8 = 0b1000
// BUF_SIZE - 1 = 7 = 0b0111
// x & 7 等价于 x % 8（仅当 x >= 0 时成立）
```

### 4.2 哈希计算中的自然溢出

字符串哈希算法常利用 `unsigned long long` 的自然回绕作为模运算，避免显式取模的开销：

```c
#include <stdio.h>
#include <string.h>
#include <stdint.h>

// 自然溢出哈希：利用 uint64_t 的回绕自动对 2^64 取模
uint64_t hash_string(const char *s) {
    uint64_t h = 0;
    while (*s) {
        h = h * 131 + (uint64_t)(*s);  // 回绕自动发生！
        s++;
    }
    return h;
}

// 等价于：h = h * 131 + c (mod 2^64)
// 无需手动写 % (2^64)，编译器自动处理

int main(void) {
    printf("hash(\"hello\") = %llu\n",
           (unsigned long long)hash_string("hello"));
    printf("hash(\"world\") = %llu\n",
           (unsigned long long)hash_string("world"));
    return 0;
}
```

### 4.3 时钟比较（Linux 内核技术）

Linux 内核中的 `time_before()` / `time_after()` 宏利用无符号回绕实现**正确的时钟比较**，即使时钟计数器发生回绕也能正确判断先后：

```c
#include <stdio.h>
#include <stdint.h>

// Linux 内核风格的时钟比较宏
// 原理：将时间差转换为有符号整数，利用有符号比较判断先后
#define time_after(known, unknown) \
    ((int32_t)(unknown) - (int32_t)(known) < 0)

#define time_before(known, unknown) \
    ((int32_t)(unknown) - (int32_t)(known) > 0)

int main(void) {
    // 模拟 32 位时钟计数器（接近回绕边界）
    uint32_t now = 0xFFFFFFF0;   // 接近 UINT32_MAX
    uint32_t expire = 0x00000010; // 已经"回绕"过了

    // 直觉上 expire（16）< now（4294967280），expire 应该"更早"
    // 但考虑到回绕，expire 实际上在 now 之后 32 个时钟周期

    if (time_before(now, expire)) {
        printf("expire 在 now 之后（正确！考虑了回绕）\n");
    } else {
        printf("expire 在 now 之前\n");
    }

    // 如果用普通比较：
    if (expire < now) {
        printf("普通比较：expire < now（错误！忽略了回绕）\n");
    }

    return 0;
}
```

> 这个技巧的核心在于：两个无符号时间戳的**差值**（即使发生了回绕）转换为有符号整数后，其**符号**仍然正确反映了时间的先后关系。

### 4.4 循环索引的自然回绕

```c
// 利用回绕实现无限循环索引
uint8_t index = 0;
for (int i = 0; i < 300; i++) {
    buffer[index] = data[i];
    index++;  // 0→1→...→255→0→1→... 自动回绕
}
```

## 5. 回绕导致的陷阱

### 5.1 递减循环死循环

```c
// ❌ 死循环！unsigned 永远 >= 0
for (unsigned int i = 10; i >= 0; i--) {
    printf("%u ", i);
}
// i 从 10 递减到 0，然后 0 - 1 回绕为 UINT_MAX（4294967295）
// UINT_MAX >= 0 永远为真 → 死循环

// ✅ 正确写法
for (int i = 10; i >= 0; i--) {
    printf("%d ", i);
}
```

### 5.2 无符号减法"永远非负"

```c
unsigned int a = 5, b = 10;

// ❌ 错误：a - b 回绕为一个巨大的正数，不是负数！
if (a - b < 0) {         // 永远为假！
    printf("a < b\n");
}

// ✅ 正确：直接比较大小
if (a < b) {
    printf("a < b\n");
}
```

### 5.3 回绕后的溢出检查无效

```c
unsigned int sum = 4000000000U;
unsigned int add = 500000000U;

// ❌ 错误：sum + add 已经回绕，检查结果是否 > UINT_MAX 无意义
if (sum + add > UINT_MAX) {   // 永远为假！
    printf("溢出！\n");
}

// ✅ 正确：在加法之前检查
if (add > UINT_MAX - sum) {
    printf("溢出！\n");
} else {
    sum = sum + add;
}
```

### 5.4 `sizeof` / `strlen` 参与运算时的回绕

```c
char arr[10];
int offset = -1;

// ❌ 危险：sizeof 返回 size_t（无符号）
// sizeof(arr) + offset → offset 被转为 size_t（巨大正数）
size_t pos = sizeof(arr) + offset;  // 不是 9，而是一个巨大的数！

// ✅ 正确：统一类型后再运算
size_t pos2 = (int)sizeof(arr) + offset;  // 9
```

## 6. 回绕安全检测

### 6.1 加法检测模式

```c
#include <stdint.h>
#include <limits.h>

// 检测 uint32_t 加法是否会回绕
int will_add_wrap(uint32_t a, uint32_t b) {
    return a > UINT32_MAX - b;  // 不会自身回绕的安全检查
}

// 安全加法：返回 1 表示成功，0 表示将回绕
int safe_uadd(uint32_t a, uint32_t b, uint32_t *result) {
    if (a > UINT32_MAX - b) return 0;
    *result = a + b;
    return 1;
}
```

### 6.2 减法检测模式

```c
// 检测 uint32_t 减法是否会回绕
int will_sub_wrap(uint32_t a, uint32_t b) {
    return b > a;  // 被减数 < 减数 → 将回绕
}

// 安全减法
int safe_usub(uint32_t a, uint32_t b, uint32_t *result) {
    if (b > a) return 0;
    *result = a - b;
    return 1;
}
```

### 6.3 乘法检测模式

```c
// 检测 uint32_t 乘法是否会回绕
int will_mul_wrap(uint32_t a, uint32_t b) {
    if (a == 0 || b == 0) return 0;
    return a > UINT32_MAX / b;
}

// 安全乘法
int safe_umul(uint32_t a, uint32_t b, uint32_t *result) {
    if (a != 0 && b > UINT32_MAX / a) return 0;
    *result = a * b;
    return 1;
}
```

### 6.4 使用编译器内建函数（推荐）

```c
#include <stdint.h>

// GCC/Clang 内建函数，一条语句搞定
uint32_t a = 4000000000U, b = 500000000U, result;

if (__builtin_add_overflow(a, b, &result)) {
    // 将发生回绕
    printf("加法回绕！\n");
} else {
    printf("result = %u\n", result);
}
```

## 7. 真实工程案例

### 7.1 波音 787 发电机控制单元回绕（2015 年）

2015 年，美国联邦航空管理局（FAA）发布适航指令，指出波音 787 的发电机控制单元（GCU）中存在一个软件计数器回绕缺陷：

- **问题**：GCU 内部的一个计数器在连续运行 **248 天**后发生回绕
- **后果**：所有六个发电机控制单元**同时**进入安全模式，导致飞机完全失去电力
- **修复**：FAA 要求航空公司定期重启飞机电力系统，直到波音发布软件补丁

> 教训：即使是"不会崩溃"的回绕，如果业务逻辑不期望它发生，后果可能是灾难性的。

### 7.2 阿里余额宝整数下溢漏洞（2015 年）

2015 年，安全研究人员发现支付宝余额宝存在整数下溢漏洞：

```c
// 漏洞模式（简化示意）
unsigned int balance = 100;
unsigned int withdraw = 200;

// 回绕检查错误：balance - withdraw 回绕为巨大正数
if (balance - withdraw > 0) {   // 条件为真！绕过了余额检查
    balance = balance - withdraw;
}

// 安全写法：
if (balance >= withdraw) {
    balance -= withdraw;
}
```

### 7.3 YouTube 播放量计数器溢出（2014 年）

2014 年，Psy 的《Gangnam Style》成为首个突破 `INT_MAX`（约 21 亿）的视频，YouTube 后端使用 32 位有符号整数存储播放量，溢出后计数器变为负数。解决方案是将计数器从 `int32_t` 升级为 `int64_t`。

## 8. 回绕 vs 有符号溢出：根本区别

|维度|无符号回绕|有符号溢出|
|---|---|---|
|**标准定义**|定义良好（mod 2^N）|未定义行为（UB）|
|**可预测性**|✅ 完全可预测|❌ 完全不可预测|
|**编译器优化**|不会被优化掉|可能被优化掉|
|**安全检测**|可在运算前检查|必须在运算前检查（事后已晚）|
|**依赖程度**|可以放心依赖|绝不能依赖|
|**典型应用**|环形缓冲区、哈希、时钟|无（应避免）|

```c
// 无符号回绕：安全、可预测
uint32_t u = UINT32_MAX;
u = u + 1;  // u = 0，完全合法，所有编译器行为一致

// 有符号溢出：危险、不可预测
int s = INT_MAX;
s = s + 1;  // ⚠️ UB！可能得到 INT_MIN，也可能得到别的
             // 编译器甚至可能优化掉后续的溢出检查代码
```

## 9. 速查表

### 回绕行为速查

|类型|位宽 N|模数 2^N|上溢回绕|下溢回绕|
|---|---|---|---|---|
|`uint8_t`|8|256|255 + 1 → 0|0 - 1 → 255|
|`uint16_t`|16|65536|65535 + 1 → 0|0 - 1 → 65535|
|`uint32_t`|32|4294967296|4294967295 + 1 → 0|0 - 1 → 4294967295|
|`uint64_t`|64|1.8 × 10¹⁹|MAX + 1 → 0|0 - 1 → MAX|

### 回绕安全检测速查

|运算|检测条件（将回绕）|安全写法|
|---|---|---|
|`a + b`|`a > MAX - b`|先检查再相加|
|`a - b`|`b > a`|先检查再相减|
|`a * b`|`a != 0 && b > MAX / a`|先检查再相乘|
|`a + 1`|`a == MAX`|先检查再递增|
|`a - 1`|`a == 0`|先检查再递减|

### 回绕口诀

> **无符号回绕是朋友，定义明确可依赖；**  
> **有符号溢出是敌人，未定义行为莫依赖。**  
> **运算之前先检查，减法比较别做差。**  
> **环形缓冲哈希表，回绕用得好法宝。**
