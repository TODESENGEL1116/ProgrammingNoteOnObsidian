## 1. 概念总览

上溢和下溢描述的是**运算结果超出目标类型表示范围**的情况，但整数和浮点数的行为截然不同：

| 维度        | 整数上溢/下溢          | 浮点上溢/下溢          |
| --------- | ---------------- | ---------------- |
| **上溢**    | 结果 > 类型最大值       | 结果 > 类型最大有限值     |
| **下溢**    | 结果 < 类型最小值       | 结果接近零，精度丢失       |
| **有符号整数** | ⚠️ **未定义行为（UB）** | —                |
| **无符号整数** | ✅ 定义良好（回绕）       | —                |
| **浮点数**   | —                | ⚠️ 产生 ±inf 或触发异常 |

### 各整数类型范围速查

|类型|最小值|最大值|位数|
|---|---|---|---|
|`int8_t`|−128|127|8|
|`uint8_t`|0|255|8|
|`int16_t`|−32,768|32,767|16|
|`uint16_t`|0|65,535|16|
|`int32_t`|−2,147,483,648|2,147,483,647|32|
|`uint32_t`|0|4,294,967,295|32|
|`int64_t`|−9.2 × 10¹⁸|9.2 × 10¹⁸|64|
|`uint64_t`|0|1.8 × 10¹⁹|64|

> 以上为 `<stdint.h>` 中固定宽度类型的精确范围。`int`、`long` 等基本类型的范围依赖平台，可通过 `<limits.h>` 中的宏获取。

## 2. 整数上溢（Integer Overflow）

### 2.1 无符号整数：定义良好的回绕

C 标准明确规定：无符号整数运算**永远不会溢出**。当结果超出表示范围时，自动对 2^N 取模（N 为位宽）。

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    // 无符号 8 位：范围 0 ~ 255
    uint8_t u = 255;
    u = u + 1;    // 256 % 256 = 0，回绕到 0
    printf("255 + 1 = %u\n", u);   // 输出: 0

    uint8_t v = 0;
    v = v - 1;    // -1 + 256 = 255，回绕到 255
    printf("0 - 1 = %u\n", v);     // 输出: 255

    // 无符号 32 位：范围 0 ~ 4294967295
    uint32_t big = UINT32_MAX;
    big = big + 1;
    printf("UINT32_MAX + 1 = %u\n", big);  // 输出: 0

    return 0;
}
```

> 这种回绕行为是**C 标准保证的**，可以放心依赖。常用于环形缓冲区、哈希计算等场景。

### 2.2 有符号整数：未定义行为（UB）

有符号整数溢出是**未定义行为**——编译器可以做任何事，包括看似"正常"的结果、优化掉检查代码、甚至导致程序崩溃。

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    // int 范围（32 位）：-2147483648 ~ 2147483647
    int a = INT_MAX;       // 2147483647
    int b = a + 1;         // ⚠️ 未定义行为！
    printf("%d\n", b);     // 可能输出 -2147483648，也可能输出别的

    int c = INT_MIN;       // -2147483648
    int d = c - 1;         // ⚠️ 未定义行为！

    // 乘法溢出
    int e = 1000000;
    int f = e * e;         // ⚠️ 10^12 远超 INT_MAX，未定义行为

    return 0;
}
```

#### 为什么 UB 如此危险？

编译器会**假设 UB 永远不会发生**，并据此进行优化：

```c
// 编译器认为有符号溢出不可能发生，因此认为 x + 1 一定 > x
// 这个检查可能被优化掉！
int safe_add(int x, int y) {
    int result = x + y;
    if (result < x) {      // 编译器可能认为这永远为假
        return -1;          // 溢出保护代码可能被删除！
    }
    return result;
}

// 安全写法：在溢出发生前检查
int safe_add(int x, int y) {
    if (y > 0 && x > INT_MAX - y) return -1;  // 先检查
    if (y < 0 && x < INT_MIN - y) return -1;
    return x + y;
}
```

#### 有符号溢出的常见触发场景

|场景|示例|说明|
|---|---|---|
|加法|`INT_MAX + 1`|超过最大值|
|减法|`INT_MIN - 1`|低于最小值|
|乘法|`100000 * 100000`|结果超出范围|
|取反|`-INT_MIN`|`INT_MIN` 没有对应的正数（补码不对称）|
|除法|`INT_MIN / -1`|结果应为 `INT_MAX + 1`，超出范围|

```c
// 特别容易忽视的两个：
int x = INT_MIN;
int y = -x;     // ⚠️ UB！-(-2147483648) = 2147483648 > INT_MAX
int z = x / -1; // ⚠️ UB！同上
```

### 2.3 有符号溢出的安全检测

```c
#include <limits.h>
#include <stdint.h>

// 安全加法
int safe_add(int a, int b, int *result) {
    if (b > 0 && a > INT_MAX - b) return 0;  // 将溢出
    if (b < 0 && a < INT_MIN - b) return 0;  // 将下溢
    *result = a + b;
    return 1;
}

// 安全乘法（此示例假设 a ≠ 0 且 b ≠ 0 时可安全做除法检查）
int safe_mul(int a, int b, int *result) {
    if (a > 0 && b > 0 && a > INT_MAX / b) return 0;
    if (a > 0 && b < 0 && b < INT_MIN / a) return 0;
    if (a < 0 && b > 0 && a < INT_MIN / b) return 0;
    if (a < 0 && b < 0 && a < INT_MAX / b) return 0;
    *result = a * b;
    return 1;
}

// C99 起可用 <stdint.h> 中的宽类型检测
int safe_add_64(int a, int b, int *result) {
    int64_t wide = (int64_t)a + b;
    if (wide > INT_MAX || wide < INT_MIN) return 0;
    *result = (int)wide;
    return 1;
}
```

## 3. 整数下溢（Integer Underflow）

"整数下溢"通常指有符号整数减法结果低于最小值，或有符号整数运算结果低于最小可表示值。本质上它和有符号上溢一样，都是**未定义行为**。

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    int a = INT_MIN;     // -2147483648
    int b = a - 1;       // ⚠️ 未定义行为！结果应为 -2147483649

    // 循环中的典型下溢
    for (int i = 10; i >= 0; i--) {
        printf("%d ", i);
    }
    // 当 i = 0 时执行循环体，然后 i-- 变为 -1，-1 >= 0 为假，循环结束。正确。
    //
    // 但如果用 unsigned：
    // for (unsigned i = 10; i >= 0; i--) { ... }
    // ⚠️ 死循环！unsigned 永远 >= 0，0 - 1 回绕为 UINT_MAX

    return 0;
}
```

> **经典 bug**：用 `unsigned` 类型做递减循环时，`i >= 0` 永远为真，导致死循环。

## 4. 浮点上溢（Floating-Point Overflow）

### 4.1 行为定义

当浮点运算的**精确结果**的绝对值大于目标类型能表示的最大有限值时，发生浮点上溢。根据 IEEE 754 和 C 标准：

- **默认舍入模式（roundTiesToEven）**：结果为 **±∞**（同号无穷大）
- **向零舍入（roundTowardZero）**：结果为该类型的**最大有限值**（如 `FLT_MAX`）
- 同时设置浮点环境中的 **overflow 异常标志**

```c
#include <stdio.h>
#include <float.h>
#include <math.h>

int main(void) {
    // float 上溢
    float f = FLT_MAX;         // float 最大值 ≈ 3.4 × 10^38
    f = f * 2.0f;             // 超出范围
    printf("f = %f\n", f);    // 输出: inf
    printf("isinf: %d\n", isinf(f));  // 输出: 1

    // double 上溢
    double d = DBL_MAX;        // double 最大值 ≈ 1.8 × 10^308
    d = d * 2.0;
    printf("d = %f\n", d);    // 输出: inf

    // 渐进式上溢：从合法值逐步增长
    double x = 1e300;
    x = x * 1e10;             // 1e310 > DBL_MAX → inf
    printf("x = %e\n", x);   // 输出: inf

    return 0;
}
```

### 4.2 上溢后的传播

一旦产生 `inf`，后续运算会按 IEEE 754 规则传播：

```c
double inf = 1.0 / 0.0;     // +inf

printf("%f\n", inf + 1.0);   // inf（inf + 有限值 = inf）
printf("%f\n", inf * 2.0);   // inf
printf("%f\n", inf - inf);   // NaN（inf - inf 无意义）
printf("%f\n", inf / inf);   // NaN
printf("%f\n", 1.0 / inf);   // 0.0
printf("%f\n", inf / 0.0);   // inf
```

## 5. 浮点下溢（Floating-Point Underflow）

### 5.1 行为定义

浮点下溢发生在运算结果的**精确值**非零但其绝对值小于目标类型能表示的最小正规化数时。这是一个**渐进过程**，分为两个阶段：

**第一阶段：渐进下溢（Gradual Underflow）**

当精确结果小于最小正规化数（`FLT_MIN`）但大于等于最小次正规数时，结果以**次正规数（subnormal/denormal）**表示。此时精度逐渐丢失（有效位数减少），但结果不为零。

**第二阶段：下溢到零**

当精确结果小于最小次正规数时，根据舍入模式，结果被舍入为零或最小次正规数。此时设置浮点环境中的 **underflow 异常标志**。

```c
#include <stdio.h>
#include <float.h>
#include <math.h>

int main(void) {
    // 最小正规化 float ≈ 1.175494e-38
    printf("FLT_MIN = %e\n", FLT_MIN);

    // 最小次正规 float ≈ 1.401298e-45
    // 可通过 FLT_TRUE_MIN（C11）获取

    // 渐进下溢：结果进入次正规范围
    float a = FLT_MIN;          // 最小正规化数
    float b = a / 2.0f;        // 进入次正规范围，不为零！
    printf("FLT_MIN / 2 = %e\n", b);  // 输出: 5.877472e-39（次正规数）

    // 继续缩小
    float c = b / 2.0f;
    printf("FLT_MIN / 4 = %e\n", c);  // 输出: 2.938736e-39

    // 最终下溢到零
    float tiny = 1e-45f;
    float zero = tiny * 1e-10f;
    printf("tiny * 1e-10 = %e\n", zero);  // 输出: 0.000000e+00

    return 0;
}
```

### 5.2 次正规数的精度损失

次正规数的有效位数比正规数少，这意味着**精度逐渐丢失**：

```c
#include <stdio.h>
#include <float.h>

int main(void) {
    // 正规数：23 位尾数，约 7 位十进制有效数字
    float normal = 1.0000001f;
    printf("正规数: %.10f\n", normal);  // 精度完整

    // 次正规数：尾数位数减少，精度降低
    float sub = FLT_MIN / 4.0f;
    float sub2 = sub + FLT_MIN / 8.0f;
    printf("次正规数: %e\n", sub);
    printf("次正规数 + 小量: %e\n", sub2);
    // 在次正规范围内，两个不同的小数可能无法区分

    return 0;
}
```

### 5.3 浮点下溢的实际影响

浮点下溢通常不会导致程序崩溃，但可能引发：

- **精度丢失**：次正规数的计算精度显著降低
- **性能下降**：某些 CPU 对次正规数的处理需要额外的微码操作，性能损失视架构和编译选项而定（见下文详述）
- **逻辑错误**：本应非零的结果变为零，影响后续判断

#### 次正规数的性能惩罚（因架构而异）

|架构 / 模式|性能影响|说明|
|---|---|---|
|x86（SSE2 模式）|通常 2~3 倍损失|现代 CPU 已大幅优化|
|x86（x87 模式）|可能慢 10~100 倍|旧式浮点单元处理次正规数效率极低|
|ARM Cortex-M|可能慢 10~100 倍|无硬件次正规支持时需软件模拟|
|ARM Cortex-A（NEON）|通常无额外惩罚|硬件直接支持|

> **生产环境建议**：若确定不需要次正规数精度，可在编译或运行时将其刷新为零（Flush-To-Zero），避免性能陷阱：

```c
// 方法 1：编译时选项（推荐）
// GCC/Clang: -ffast-math 或 -msse -mfpmath=sse
// 注意：-ffast-math 会放宽 IEEE 754 合规性，可能影响其他浮点语义

// 方法 2：运行时控制（x86）
#include <xmmintrin.h>
_MM_SET_FLUSH_ZERO_MODE(_MM_FLUSH_ZERO_ON);      // 输出刷新为零
_MM_SET_DENORMALS_ZERO_MODE(_MM_DENORMALS_ZERO_ON); // 输入视为零
```

## 6. 类型转换时的溢出

浮点到整数的强制转换中，若浮点值超出目标整数类型的表示范围，结果是**未定义行为**：

```c
#include <stdio.h>
#include <limits.h>
#include <math.h>

int main(void) {
    // 浮点值超出 int 范围
    double d = 1e20;
    int i = (int)d;    // ⚠️ UB！1e20 远超 INT_MAX（约 2.1 × 10^9）

    // inf 转为整数
    float f = INFINITY;
    int j = (int)f;    // ⚠️ UB！inf 无法表示为任何整数

    // NaN 转为整数
    double nan = NAN;
    int k = (int)nan;  // ⚠️ UB！NaN 无法表示为任何整数

    // 安全做法：转换前检查范围
    double safe_val = 42.7;
    if (safe_val >= (double)INT_MIN && safe_val <= (double)INT_MAX) {
        int safe_i = (int)safe_val;  // 安全
        printf("safe_i = %d\n", safe_i);
    } else {
        printf("值超出 int 范围！\n");
    }

    return 0;
}
```

> 这与整数之间的截断转换不同——整数截断是**实现定义的**（有明确结果），而浮点→整数超出范围是**未定义行为**（结果完全不可预测）。

## 7. 浮点异常的运行时检测

浮点异常标志设置在**浮点环境（floating-point environment）**中，可通过 `<fenv.h>` 检测：

```c
#include <stdio.h>
#include <math.h>
#include <fenv.h>

int main(void) {
    // 清除所有异常标志
    feclearexcept(FE_ALL_EXCEPT);

    // 触发上溢
    double x = DBL_MAX * 2.0;
    (void)x;  // 防止编译器优化掉

    // 检查 overflow 标志
    if (fetestexcept(FE_OVERFLOW)) {
        printf("发生了浮点上溢！\n");
    }

    // 清除后测试下溢
    feclearexcept(FE_ALL_EXCEPT);

    double y = DBL_MIN * 1e-300;
    (void)y;

    if (fetestexcept(FE_UNDERFLOW)) {
        printf("发生了浮点下溢！\n");
    }

    // 检查是否为 inf 或 NaN
    printf("x is inf: %d\n", isinf(x));       // 1
    printf("x is finite: %d\n", isfinite(x)); // 0

    return 0;
}
```

## 8. 特殊值与判断函数

### 8.1 IEEE 754 特殊值

|特殊值|产生方式|含义|
|---|---|---|
|`+inf`|`1.0 / 0.0`、上溢|正无穷大|
|`-inf`|`-1.0 / 0.0`、上溢|负无穷大|
|`NaN`|`0.0 / 0.0`、`inf - inf`、`sqrt(-1)`|非数（Not a Number）|
|`+0.0` / `-0.0`|下溢、`1.0 / inf`|带符号的零|

### 8.2 判断函数（`<math.h>`）

```c
#include <math.h>

double x = /* 某个值 */;

isinf(x);     // x 是 +inf 或 -inf 时返回非零
isnan(x);     // x 是 NaN 时返回非零
isfinite(x);  // x 不是 inf 也不是 NaN 时返回非零
isnormal(x);  // x 是正规数（非零、非 inf、非 NaN、非次正规）时返回非零
signbit(x);   // x 的符号位为 1 时返回非零（包括 -0.0）
```

### 8.3 NaN 的传播与陷阱

```c
double nan = 0.0 / 0.0;

// NaN 与任何值的比较都返回假（包括与自身比较！）
printf("%d\n", nan == nan);    // 输出: 0（NaN != NaN）
printf("%d\n", nan < 1.0);     // 输出: 0
printf("%d\n", nan > 1.0);     // 输出: 0

// NaN 参与运算后结果仍为 NaN
printf("%f\n", nan + 1.0);     // nan
printf("%f\n", nan * 2.0);     // nan

// 正确检测 NaN 的方法
if (isnan(x)) {
    printf("x 是 NaN\n");
}
```

## 9. 整数 vs 浮点：行为对比总结

|场景|无符号整数|有符号整数|浮点数|
|---|---|---|---|
|**超过最大值**|回绕到 0（定义良好）|⚠️ 未定义行为|产生 +inf|
|**低于最小值**|回绕到最大值（定义良好）|⚠️ 未定义行为|产生 -inf 或 0|
|**除以零**|⚠️ 未定义行为|⚠️ 未定义行为|正数/0.0→+inf，负数/0.0→-inf，0.0/0.0→NaN|
|**精度丢失**|不适用（精确运算）|不适用（精确运算）|渐进发生（次正规数）|
|**结果可预测性**|✅ 完全可预测|❌ 完全不可预测|✅ 由 IEEE 754 定义|

## 10. 编译器内建溢出检测函数

手动写溢出检查既繁琐又容易出错。GCC/Clang 提供了内建函数，一条语句搞定，且在底层利用 CPU 的溢出标志位（如 x86 的 `OF` 标志），比手动比较更高效：

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    int a = INT_MAX, b = 1, result;

    // 加法溢出检测
    if (__builtin_add_overflow(a, b, &result)) {
        printf("加法溢出！\n");
    } else {
        printf("result = %d\n", result);
    }

    // 减法溢出检测
    int c = INT_MIN, d = 1, result2;
    if (__builtin_sub_overflow(c, d, &result2)) {
        printf("减法溢出！\n");
    } else {
        printf("result2 = %d\n", result2);
    }

    // 乘法溢出检测
    int e = 1000000, f = 1000000, result3;
    if (__builtin_mul_overflow(e, f, &result3)) {
        printf("乘法溢出！\n");
    } else {
        printf("result3 = %d\n", result3);
    }

    return 0;
}
```

> **适用编译器**：GCC 5+、Clang 3.8+。MSVC 无对应内建函数，但可通过 `<intrin.h>` 中的 `_addcarry_u32` 等实现类似功能。

## 11. 常见陷阱与最佳实践

### 11.1 整数运算前的范围检查

```c
// ❌ 错误：先运算再检查（UB 已经发生了）
int multiply(int a, int b) {
    int result = a * b;
    if (result / a != b) return -1;  // 太晚了，UB 已发生；且 a=0 时除零
    return result;
}

// ✅ 正确：先检查再运算
int multiply(int a, int b) {
    if (a > 0 && b > 0 && a > INT_MAX / b) return -1;
    if (a > 0 && b < 0 && b < INT_MIN / a) return -1;
    if (a < 0 && b > 0 && a < INT_MIN / b) return -1;
    if (a < 0 && b < 0 && a < INT_MAX / b) return -1;
    return a * b;
}

// ✅ 更简洁：使用编译器内建函数
int multiply_builtin(int a, int b, int *result) {
    if (__builtin_mul_overflow(a, b, result)) return -1;
    return 0;
}
```

### 11.2 浮点运算前的范围检查

```c
// 防止上溢
double safe_multiply(double a, double b) {
    if (isinf(a) || isinf(b)) return (a > 0) == (b > 0) ? INFINITY : -INFINITY;
    if (a != 0.0 && fabs(b) > DBL_MAX / fabs(a)) {
        return (a > 0) == (b > 0) ? INFINITY : -INFINITY;
    }
    return a * b;
}

// 防止下溢导致的精度问题
double safe_divide(double a, double b) {
    if (b == 0.0) return a > 0 ? INFINITY : -INFINITY;
    double result = a / b;
    if (result != 0.0 && !isnormal(result) && a != 0.0) {
        // 结果进入次正规范围，精度可能不足
        // 根据业务需求决定是否报警
    }
    return result;
}
```

### 11.3 避免 unsigned 递减循环的死循环

```c
// ❌ 死循环！unsigned 永远 >= 0
for (unsigned i = 10; i >= 0; i--) {
    printf("%u ", i);
}

// ✅ 正确写法 1：用有符号类型
for (int i = 10; i >= 0; i--) {
    printf("%d ", i);
}

// ✅ 正确写法 2：改用前置条件
for (unsigned i = 10; i != (unsigned)-1; i--) {
    printf("%u ", i);
}

// ✅ 正确写法 3：从 0 递增
for (unsigned i = 0; i <= 10; i++) {
    printf("%u ", 10 - i);
}
```

### 11.4 `-INT_MIN` 和 `INT_MIN / -1` 的陷阱

```c
int x = INT_MIN;

// 这两个都是未定义行为！
int y = -x;        // -(-2147483648) = 2147483648 > INT_MAX
int z = x / -1;    // 同上

// 安全写法
int safe_negate(int x) {
    if (x == INT_MIN) return INT_MAX;  // 或返回错误码
    return -x;
}

int safe_divide(int a, int b) {
    if (b == 0) return 0;  // 或返回错误码
    if (a == INT_MIN && b == -1) return INT_MAX;
    return a / b;
}
```

## 12. 真实工程中的经典案例

### 12.1 Y2038 问题

`time_t` 在 32 位系统上通常是 `int32_t`（有符号 32 位整数），表示自 1970-01-01 00:00:00 UTC 以来的秒数。

```c
// 2038-01-19 03:14:07 UTC → INT_MAX = 2147483647
// 下一秒 → 有符号溢出 → 未定义行为（通常变为负数）
// 系统会认为时间回到了 1901-12-13！

// 影响范围：嵌入式系统、旧版 Linux、路由器、数据库等
// 解决方案：使用 64 位 time_t（已在多数现代系统中实现）
```

### 12.2 YouTube 播放量计数器溢出

2014 年，Psy 的《Gangnam Style》成为 YouTube 首个播放量突破 `INT_MAX`（2,147,483,647，约 21 亿）的视频。YouTube 后端使用 32 位有符号整数存储播放量，溢出后计数器变为负数。

```c
// 解决方案：将计数器从 int32_t 升级为 int64_t
// int64_t 最大值 ≈ 9.2 × 10^18，足以支撑数千年
```

### 12.3 阿里余额宝整数下溢漏洞（2015 年）

2015 年，安全研究人员发现支付宝余额宝存在整数下溢漏洞。攻击者通过精心构造的转账金额，利用整数下溢绕过金额校验逻辑，可能导致资金异常。

```c
// 典型的漏洞模式（简化示意）：
unsigned int balance = 100;
unsigned int withdraw = 200;

if (balance - withdraw > 0) {   // 100 - 200 回绕为一个巨大的正数
    // 条件为真！绕过了余额检查
    balance = balance - withdraw;
}

// 安全写法：
if (balance >= withdraw) {
    balance -= withdraw;
}
```

## 13. 编译器保护选项

|选项|作用|
|---|---|
|`-fsanitize=undefined`|运行时检测所有未定义行为（包括有符号溢出）|
|`-fsanitize=signed-integer-overflow`|仅检测有符号整数溢出|
|`-fsanitize=float-divide-by-zero`|检测浮点除以零|
|`-fsanitize=float-cast-overflow`|检测浮点到整数的转换溢出|
|`-fwrapv`|强制有符号溢出按回绕处理（非标准，但实用）|
|`-ftrapv`|有符号溢出时触发陷阱（SIGABRT）|

```bash
# 开发阶段推荐：检测所有未定义行为
gcc -fsanitize=undefined -g main.c -o main

# 生产环境：强制有符号溢出回绕（牺牲标准合规性换取可预测性，
# 且可能影响编译器的优化效果，因为编译器无法再假设溢出不发生）
gcc -fwrapv -O2 main.c -o main
```

## 14. 速查表

### 上溢/下溢行为速查

|类型|操作|超出最大值|低于最小值|
|---|---|---|---|
|`unsigned int`|`+` `*`|回绕（mod 2^N）|回绕（mod 2^N）|
|`signed int`|`+` `-` `*`|⚠️ UB|⚠️ UB|
|`signed int`|`/` `%`|`INT_MIN / -1` → UB|—|
|`signed int`|取反|`-INT_MIN` → UB|—|
|`float` / `double`|任意|→ ±inf|→ 次正规数或 0|
|`float` → `int`|强制转换|超出 INT_MAX → UB|低于 INT_MIN → UB|

### 关键数值速查（32 位 int / IEEE 754 float）

|常量|值|说明|
|---|---|---|
|`INT_MAX`|2,147,483,647|int 最大值|
|`INT_MIN`|−2,147,483,648|int 最小值|
|`UINT_MAX`|4,294,967,295|unsigned int 最大值|
|`FLT_MAX`|≈ 3.4 × 10³⁸|float 最大有限值|
|`FLT_MIN`|≈ 1.18 × 10⁻³⁸|float 最小正规化值|
|`DBL_MAX`|≈ 1.8 × 10³⁰⁸|double 最大有限值|
|`DBL_MIN`|≈ 2.2 × 10⁻³⁰⁸|double 最小正规化值|

### 溢出检测方式速查

|方式|适用场景|优点|缺点|
|---|---|---|---|
|手动范围检查|所有编译器|可移植|繁琐、易出错|
|`__builtin_*_overflow`|GCC 5+、Clang 3.8+|简洁、高效|不可移植到 MSVC|
