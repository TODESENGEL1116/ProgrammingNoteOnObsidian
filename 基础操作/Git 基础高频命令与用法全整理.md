
这份整理覆盖了日常开发 90% 的使用场景，按功能模块分类，从入门到进阶均可直接查阅使用。

---
#### 一、基础配置（首次使用必设置）

| 命令                                      | 说明                 |
| --------------------------------------- | ------------------ |
| `git config --global user.name "你的名字"`  | 设置全局用户名，提交时显示的身份标识 |
| `git config --global user.email "你的邮箱"` | 设置全局邮箱，提交时显示的身份标识  |
| `git config --global core.editor vim`   | 设置默认编辑器            |
| `git config --list`                     | 查看当前所有配置项          |

> 💡 建议每个开发者设置一次即可，配置保存在 `~/.gitconfig` 文件中，后续所有仓库通用。

#### 二、仓库初始化与克隆

|命令|说明|
|---|---|
|`git init`|在当前目录初始化一个新的 Git 仓库|
|`git init 项目名`|创建新目录并初始化为 Git 仓库|
|`git clone <仓库地址>`|克隆远程仓库到本地，自动创建同名目录|
|`git clone <仓库地址> 自定义目录名`|克隆远程仓库到指定名称的目录|

#### 三、核心工作流（最高频）

这是 Git 最核心的三个区域之间的流转：

```
工作区 → git add → 暂存区 → git commit → 本地仓库 → git push → 远程仓库
```

|命令|说明|
|---|---|
|`git status`|查看当前仓库状态，哪些文件被修改、暂存或未跟踪|
|`git add 文件名`|将指定文件添加到暂存区|
|`git add .`|将当前目录所有变更（新增、修改、删除）添加到暂存区|
|`git commit -m "提交说明"`|将暂存区的内容提交到本地仓库，必须写提交说明|
|`git commit -am "提交说明"`|跳过 `git add`，直接提交所有已跟踪文件的修改（不含新增文件）|
|`git push`|将本地提交推送到远程仓库|
|`git pull`|从远程仓库拉取最新代码并自动合并到当前分支|

---

#### 四、查看差异与历史记录

|命令|说明|
|---|---|
|`git diff`|查看工作区与暂存区之间的差异（未 `add` 的修改）|
|`git diff --staged`|查看暂存区与最近一次提交之间的差异（已 `add` 待 `commit` 的修改）|
|`git log`|查看提交历史，按时间倒序显示|
|`git log --oneline`|精简模式，每个提交只显示一行（哈希+说明）|
|`git log --oneline --graph`|以图形化方式展示分支合并历史|
|`git log -n 5`|仅显示最近 5 条提交记录|
|`git log --author="名字"`|筛选指定作者的提交记录|
|`git show 提交哈希`|查看某次提交的详细变更内容|
|`git blame 文件名`|逐行显示文件每一行最后被谁在哪次提交中修改|

#### 五、分支管理（协作开发核心）

|命令|说明|
|---|---|
|`git branch`|查看所有本地分支，当前分支前有 `*` 标记|
|`git branch 分支名`|创建新分支（不切换）|
|`git checkout 分支名`|切换到指定分支|
|`git checkout -b 分支名`|创建并切换到新分支（等同于上面两步合并）|
|`git branch -d 分支名`|删除已合并的分支|
|`git branch -D 分支名`|强制删除分支（即使未合并）|
|`git merge 分支名`|将指定分支合并到当前分支|
|`git switch 分支名`|切换分支（Git 2.23+ 推荐替代 `checkout`）|
|`git switch -c 分支名`|创建并切换分支（Git 2.23+ 推荐替代 `checkout -b`）|

#### 六、远程仓库操作

|命令|说明|
|---|---|
|`git remote -v`|查看远程仓库地址|
|`git remote add origin <地址>`|添加远程仓库，命名为 `origin`|
|`git remote set-url origin <新地址>`|修改远程仓库地址|
|`git push origin 分支名`|推送本地分支到远程指定分支|
|`git push -u origin 分支名`|首次推送并建立上游跟踪关系，后续直接 `git push` 即可|
|`git pull origin 分支名`|拉取远程指定分支的最新代码|
|`git fetch`|拉取远程更新但不自动合并，需手动 `merge` 或 `rebase`|
|`git clone -b 分支名 <地址>`|克隆时直接指定分支|

#### 七、撤销与回退

|命令|说明|
|---|---|
|`git checkout -- 文件名`|撤销工作区修改，恢复到暂存区或最近提交的状态|
|`git restore 文件名`|撤销工作区修改（Git 2.23+ 推荐替代 `checkout --`）|
|`git reset HEAD 文件名`|将文件从暂存区移回工作区（撤销 `git add`）|
|`git restore --staged 文件名`|撤销暂存（Git 2.23+ 推荐替代 `reset HEAD`）|
|`git reset --soft HEAD~1`|回退最近一次提交，保留修改在暂存区|
|`git reset --mixed HEAD~1`|回退最近一次提交，保留修改在工作区（默认）|
|`git reset --hard HEAD~1`|回退最近一次提交，**彻底丢弃所有修改**（慎用！）|
|`git revert 提交哈希`|创建一个新提交来撤销指定提交的变更（安全，推荐用于已推送的提交）|

#### 八、暂存工作区（临时切换任务）

|命令|说明|
|---|---|
|`git stash`|将当前未提交的修改暂存起来，工作区恢复干净|
|`git stash save "说明"`|暂存并添加描述，方便后续识别|
|`git stash list`|查看所有暂存记录|
|`git stash pop`|恢复最近一次暂存并从列表中删除|
|`git stash apply`|恢复暂存但保留在列表中（可多次恢复）|
|`git stash drop`|删除最近一次暂存记录|
|`git stash clear`|清空所有暂存记录|

#### 九、标签管理

|命令|说明|
|---|---|
|`git tag`|查看所有标签|
|`git tag v1.0.0`|在当前提交打轻量标签|
|`git tag -a v1.0.0 -m "说明"`|创建带说明的附注标签（推荐）|
|`git tag v1.0.0 提交哈希`|在历史提交上打标签|
|`git push origin v1.0.0`|推送指定标签到远程|
|`git push origin --tags`|推送所有标签到远程|
|`git tag -d v1.0.0`|删除本地标签|
|`git push origin :refs/tags/v1.0.0`|删除远程标签|

#### 十、常用进阶技巧

|命令|说明|
|---|---|
|`git rebase 分支名`|变基，将当前分支的提交"移植"到目标分支之上，保持提交历史线性整洁|
|`git cherry-pick 提交哈希`|挑选某次提交应用到当前分支|
|`git reflog`|查看所有操作记录（包括已回退的提交），是"后悔药"的终极手段|
|`git shortlog -sn`|统计每位作者的提交次数|
|`git log --stat`|查看每次提交修改了哪些文件及增删行数|
|`git log -p 文件名`|查看某个文件的完整修改历史|
|`git bisect`|二分查找法定位引入 Bug 的提交|

#### 十一、新手避坑提示

- **提交前必做**：先 `git status` 确认变更文件，避免误提交临时文件或敏感信息。
- **`.gitignore` 很重要**：在项目根目录创建 `.gitignore` 文件，忽略 `node_modules/`、`.env`、`*.log` 等不需要版本控制的文件。
- **慎用 `git reset --hard`**：该命令会彻底丢弃修改且无法直接恢复，操作前务必确认。如果已经推送过，优先用 `git revert` 代替。
- **提交说明要清晰**：遵循团队规范，比如 `feat: 新增登录功能`、`fix: 修复首页白屏问题`，方便后续追溯。
- **冲突解决**：`merge` 或 `pull` 出现冲突时，手动编辑冲突文件，保留需要的代码后 `git add` + `git commit` 完成合并。
- **推送前先拉取**：多人协作时，推送前先 `git pull` 拉取远程最新代码，减少冲突概率。
