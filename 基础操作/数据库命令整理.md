这份整理按「SQL 标准分类 → 主流关系型数据库运维 → NoSQL」三层展开。日常使用频率最高的部分是 **DQL 查询、索引、事务和 MySQL 运维命令**，可直接跳到对应章节查阅。

### 一、SQL 语句五大分类（总览）

|分类|全称|主要命令|作用|
|---|---|---|---|
|DDL|Data Definition Language|`CREATE / ALTER / DROP / TRUNCATE`|定义结构（库、表、索引、视图）|
|DML|Data Manipulation Language|`INSERT / UPDATE / DELETE / MERGE`|操作数据|
|DQL|Data Query Language|`SELECT`|查询数据|
|TCL|Transaction Control Language|`COMMIT / ROLLBACK / SAVEPOINT`|事务控制|
|DCL|Data Control Language|`GRANT / REVOKE`|权限控制|

> 记忆要点：**DDL 自动提交事务**（隐式 commit），`TRUNCATE` 是 DDL 而非 DML，不能回滚；`DELETE` 是 DML，可以回滚。

### 二、DDL：库与表

```sql
-- 库
CREATE DATABASE IF NOT EXISTS mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
DROP DATABASE IF EXISTS mydb;
USE mydb;

-- 表
CREATE TABLE users (
  id        BIGINT       PRIMARY KEY AUTO_INCREMENT,
  username  VARCHAR(64)  NOT NULL UNIQUE,
  email     VARCHAR(128) DEFAULT NULL,
  age       INT          UNSIGNED DEFAULT 0,
  status    TINYINT      DEFAULT 1 COMMENT '1正常 0禁用',
  created_at DATETIME    DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME    DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_username (username),
  INDEX idx_status_age (status, age)      -- 联合索引
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 修改表
ALTER TABLE users ADD COLUMN phone VARCHAR(20) AFTER email;
ALTER TABLE users MODIFY COLUMN email VARCHAR(255) NOT NULL;   -- 改类型/约束
ALTER TABLE users CHANGE COLUMN old_name new_name VARCHAR(50); -- 改名
ALTER TABLE users DROP COLUMN phone;
ALTER TABLE users ADD INDEX idx_email(email);
ALTER TABLE users DROP INDEX idx_email;
ALTER TABLE users AUTO_INCREMENT = 1000;
RENAME TABLE users TO user_info;

-- 清空 / 删除
TRUNCATE TABLE users;   -- DDL，重置自增，快
DROP TABLE IF EXISTS users;
```

### 三、DML：增删改

```sql
INSERT INTO users (username, email, age) VALUES ('alice','a@x.com',20);
INSERT INTO users (username, email, age) VALUES ('bob','b@x.com',25),('carol','c@x.com',30);
INSERT INTO users SELECT username, email, age FROM tmp_users;     -- 子查询插入
REPLACE INTO users (id, username) VALUES (1,'alice2');            -- MySQL：主键冲突则先删后插
INSERT ... ON DUPLICATE KEY UPDATE age = age + 1;                 -- MySQL Upsert

UPDATE users SET age = 21, updated_at = NOW() WHERE id = 1 LIMIT 1;
DELETE FROM users WHERE id = 1;
DELETE FROM users;                  -- 逐行删，可回滚，自增不重置
MERGE INTO t USING s ON (t.id=s.id) WHEN MATCHED THEN UPDATE ...  -- Oracle/PG 风格 Upsert
```

> 安全习惯：**写 UPDATE/DELETE 前先写成 SELECT 跑一遍**，确认 WHERE 范围；生产环境务必加 `LIMIT`。

### 四、DQL：查询（核心）

#### 4.1 执行顺序（决定别名能否复用）

```
FROM → JOIN → ON → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT
```

#### 4.2 基本骨架

```sql
SELECT DISTINCT u.id, u.username, COUNT(o.id) AS order_cnt
FROM users u
LEFT JOIN orders o ON u.id = o.user_id AND o.status = 1   -- JOIN 条件不影响左表行数
WHERE u.status = 1 AND u.created_at >= '2025-01-01'
GROUP BY u.id, u.username
HAVING order_cnt > 5
ORDER BY order_cnt DESC
LIMIT 20 OFFSET 0;        -- MySQL：LIMIT 20 OFFSET 0  或 LIMIT 0,20
```

#### 4.3 JOIN 类型

|写法|含义|
|---|---|
|`INNER JOIN`|只保留匹配行|
|`LEFT JOIN`|保留左表全部，右表无匹配补 NULL|
|`RIGHT JOIN`|保留右表全部|
|`FULL OUTER JOIN`|两表全保留（MySQL 不支持，用 UNION 模拟）|
|`CROSS JOIN`|笛卡尔积|
|`SELF JOIN`|同表连接（层级、上下级关系）|

#### 4.4 常用函数

- **聚合**：`COUNT(*)` / `COUNT(col)`（不计 NULL）、`SUM`、`AVG`、`MAX`、`MIN`、`GROUP_CONCAT`（MySQL）
- **数值**：`ROUND`、`CEIL`、`FLOOR`、`ABS`、`MOD`
- **字符串**：`CONCAT`、`SUBSTRING`、`LENGTH`、`TRIM`、`REPLACE`、`LOWER/UPPER`、`LIKE '%xx%'`（前缀通配符走不了索引）
- **日期**：`NOW()`、`CURDATE()`、`DATE_FORMAT(dt,'%Y-%m-%d')`、`DATEDIFF`、`DATE_ADD(dt, INTERVAL 7 DAY)`、`UNIX_TIMESTAMP`
- **空值处理**：`IFNULL(col,0)`（MySQL）、`COALESCE(a,b,c)`（通用）、`NULLIF(a,b)`
- **条件**：`CASE WHEN age>=18 THEN '成人' ELSE '未成年' END`

#### 4.5 子查询与 CTE

```sql
-- CTE（推荐，可读性好）
WITH dept_sal AS (
  SELECT dept_id, AVG(salary) AS avg_sal FROM emp GROUP BY dept_id
)
SELECT e.* FROM emp e JOIN dept_sal d ON e.dept_id=d.dept_id WHERE e.salary > d.avg_sal;

-- 相关子查询 / EXISTS
SELECT * FROM dept d WHERE EXISTS (SELECT 1 FROM emp e WHERE e.dept_id=d.dept_id);
```

#### 4.6 窗口函数（MySQL 8.0+ / PG / Oracle）

```sql
SELECT name, dept, salary,
       ROW_NUMBER() OVER (PARTITION BY dept ORDER BY salary DESC) AS rn,
       RANK()       OVER (PARTITION BY dept ORDER BY salary DESC) AS rk,
       SUM(salary)  OVER (PARTITION BY dept)           AS dept_total,
       LAG(salary)  OVER (ORDER BY hire_date)          AS prev_sal
FROM emp;
```

#### 4.7 集合运算

```sql
SELECT id FROM a UNION SELECT id FROM b;      -- 去重
SELECT id FROM a UNION ALL SELECT id FROM b;  -- 不去重（更快）
SELECT id FROM a INTERSECT SELECT id FROM b;  -- 交集（MySQL 用 INNER JOIN / IN 替代）
SELECT id FROM a EXCEPT SELECT id FROM b;     -- 差集（MySQL 用 LEFT JOIN ... IS NULL）
```

### 五、约束与索引

```sql
-- 约束
PRIMARY KEY, UNIQUE, NOT NULL, DEFAULT, CHECK (age >= 0),
FOREIGN KEY (dept_id) REFERENCES dept(id) ON DELETE CASCADE ON UPDATE RESTRICT

-- 索引
CREATE INDEX idx_name ON users(name);
CREATE UNIQUE INDEX idx_email ON users(email);
CREATE INDEX idx_composite ON orders(user_id, status, created_at);  -- 最左前缀
ALTER TABLE users DROP INDEX idx_name;
SHOW INDEX FROM users;      -- MySQL 查看索引
EXPLAIN SELECT ...;         -- 看执行计划（关注 type、key、rows、Extra）
```

**索引失效常见场景**：对索引列做函数或运算、`LIKE '%abc'` 前导通配、隐式类型转换（字符串字段不加引号）、`OR` 两侧不全有索引、联合索引违反最左前缀、`!=` / `IS NOT NULL`、低选择性列。

### 七、TCL：事务

```sql
START TRANSACTION;          -- 或 BEGIN;
SAVEPOINT sp1;
UPDATE accounts SET balance=balance-100 WHERE id=1;
ROLLBACK TO SAVEPOINT sp1;
COMMIT;                     -- 提交
ROLLBACK;                   -- 回滚

SET autocommit = 0;         -- 关闭自动提交
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

**隔离级别（由低到高）**：读未提交 → 读已提交（RC）→ 可重复读（RR，MySQL 默认）→ 串行化。对应问题：脏读、不可重复读、幻读。

### 十四、易错点与最佳实践

1. **`COUNT(*)` vs `COUNT(col)`**：前者计行数（含 NULL），后者忽略 NULL。
2. **`WHERE` 与 `ON` 的区别**：`LEFT JOIN` 中，右表条件写在 `ON` 里仍保留左表行，写在 `WHERE` 里会退化成内连接效果。
3. **NULL 比较**：`NULL = NULL` 为 UNKNOWN，必须用 `IS NULL`；`NOT IN` 遇到 NULL 会返回空集，优先用 `NOT EXISTS`。
4. **浮点数金额**：金额用 `DECIMAL(18,2)`，别用 `FLOAT/DOUBLE`。
5. **字符集**：统一 `utf8mb4`（MySQL 的 `utf8` 是三字节，存不了 emoji）。
6. **分页深翻**：`LIMIT 100000, 20` 很慢，改用「延迟关联」或游标分页 `WHERE id > #{lastId} LIMIT 20`。
7. **批量操作**：大批量 INSERT 用多值合并 + 分批（每批 1000~5000 条），避免单条循环提交。
8. **SQL 注入**：永远用参数化查询（预编译），不要字符串拼接。
9. **线上禁忌**：`DROP/TRUNCATE`、不带 WHERE 的 UPDATE/DELETE、`FLUSH PRIVILEGES` 乱刷、`ALTER TABLE` 大表不加 `ALGORITHM=INPLACE`、`DELETE` 大表不分批。
10. **排障三板斧**：`SHOW PROCESSLIST` → `EXPLAIN` → 慢查询日志（配合 `pt-query-digest`）。
