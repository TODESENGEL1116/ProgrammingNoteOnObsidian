## 核心方法（HTTP/1.1 + 常见扩展）

这些是互联网工程任务组（IETF）在 RFC 7231、RFC 5789 等文档中定义的最基础和最广泛使用的方法。

| 方法           | 描述                                             | 典型用途                                    |
| ------------ | ---------------------------------------------- | --------------------------------------- |
| **GET**​     | 请求指定的资源。只应读取数据，不应产生副作用。                        | 获取网页、查询数据。                              |
| **HEAD**​    | 与 GET 相同，但服务器只返回状态行和头部，不返回消息体。                 | 检查资源是否存在、获取文件大小（Content-Length）或最后修改时间。 |
| **POST**​    | 向指定资源提交数据，请求服务器进行处理（如创建或更新）。通常**非幂等**。         | 提交表单、上传文件、创建新资源（服务器分配ID）。               |
| **PUT**​     | 将请求的有效载荷**完整替换**目标资源。如果资源不存在则创建。是**幂等**的。      | 更新用户资料（需提交完整字段）。                        |
| **PATCH**​   | 对资源进行**部分修改**（RFC 5789）。只发送需要变更的字段。通常**非幂等**。  | 仅修改用户的邮箱，而不提交其他字段。                      |
| **DELETE**​  | 删除指定的资源。是**幂等**的（即使已删除，再次删除也不报错或返回404）。        | 删除一篇文章、注销账户。                            |
| **CONNECT**​ | 将请求连接转换为透明的 TCP/IP 隧道，通常用于 SSL 通过代理的 HTTPS 连接。 | 代理服务器建立隧道。                              |
| **OPTIONS**​ | 返回目标资源支持的 HTTP 方法。常用于跨域（CORS）预检请求。             | 查询 API 端点支持哪些操作。                        |
| **TRACE**​   | 回显客户端请求，主要用于诊断。因存在跨站追踪（XST）安全风险，通常被禁用。         | 调试请求链路。                                 |

## 关键属性速查表

理解这三个属性对于构建安全、可缓存和可靠的 API 至关重要：

|方法|安全 (Safe)|幂等 (Idempotent)|可缓存 (Cacheable)|
|---|---|---|---|
|**GET**​|✅ 是|✅ 是|✅ 是|
|**HEAD**​|✅ 是|✅ 是|✅ 是|
|**POST**​|❌ 否|❌ 否|⚠️ 仅当响应包含 Freshness 信息时|
|**PUT**​|❌ 否|✅ 是|❌ 否|
|**PATCH**​|❌ 否|❌ 否|❌ 否|
|**DELETE**​|❌ 否|✅ 是|❌ 否|
|**OPTIONS**​|✅ 是|✅ 是|❌ 否|
|**TRACE**​|✅ 是|✅ 是|❌ 否|
|**CONNECT**​|❌ 否|❌ 否|❌ 否|

> **名词解释：**
> 
> - **安全方法**：不修改服务器端资源状态（仅用于读取）。GET、HEAD、OPTIONS、TRACE 是安全的。
> - **幂等方法**：客户端发起一次或多次相同请求，对服务器产生的副作用与单次请求完全相同。PUT 和 DELETE 是幂等的，即使资源已被删除，再次 DELETE 也不会造成额外状态变化。
> - **可缓存**：响应可以被客户端或代理缓存，以减少服务器负载和带宽。


## 为什么在 HTTP 规范中 GET 比 POST “更安全”？

在 HTTP 协议语境下，**“安全方法（Safe Method）”的定义是：不修改服务器端资源状态、只用于信息获取的方法。**

- **GET 是“安全”的**：它的语义是**只读**。无论你调用一次还是一万次 GET 请求，服务器上的数据都不会发生任何变化（不会产生副作用）。比如你刷新一个网页 100 次，文章不会消失。
- **POST 是“不安全”的**：它的语义是**提交/创建**。调用 POST 请求通常会导致服务器状态改变，比如新建了一个订单、扣了一笔钱、发了一篇文章。

> 💡 **结论**：这里的“安全”是指**对服务器数据的“只读保护”**，而不是指防止数据被窃取。
