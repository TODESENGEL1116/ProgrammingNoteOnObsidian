
**Session（会话）是服务器端为每个用户创建的一块**"专属记忆空间"**，用来记录这个用户在访问网站期间的所有状态信息（比如是否已登录、购物车里有什么商品等）。

**如果说 Cookie 是服务器发给你的"会员卡"，那 Session 就是服务器后台为你建的"个人档案柜"**。会员卡（Cookie）上只写了一个编号，而档案柜（Session）里存着你的完整信息。

---

### Session 和 Cookie 的关系

它们通常是**配合使用**的：

- **Cookie**：存在浏览器端，只保存一个编号（Session ID），相当于会员卡。
- **Session**：存在服务器端，保存用户的完整数据，相当于档案柜。

#### 具体流程：

**第一步：用户登录**

```
→ 浏览器发送：
POST /login HTTP/1.1
Host: www.example.com
（用户名: zhangsan, 密码: 123456）
```

服务器验证通过后，做两件事：

1. 在服务器上创建一个 Session，存好用户信息：
    
    ```
    Session 编号: abc123
    ┌──────────────────────────────┐
    │ 用户: zhangsan               │
    │ 角色: 普通用户               │
    │ 登录时间: 2026-08-30 23:30   │
    │ 购物车: [手机壳, 耳机]       │
    └──────────────────────────────┘
    ```
    
2. 通过响应报文把 Session 编号发给浏览器：
    
    ```
    ← 服务器返回：
    HTTP/1.1 200 OK
    Set-Cookie: session_id=abc123
    ```
    

**第二步：之后的每次访问**

```
→ 浏览器自动携带：
GET /cart HTTP/1.1
Host: www.example.com
Cookie: session_id=abc123
```

服务器收到 `session_id=abc123`，去后台的"档案柜"里一查，就知道你是 zhangsan，购物车里有手机壳和耳机。

---

### Session vs Cookie 对比

| 对比项      | Cookie          | Session           |
| -------- | --------------- | ----------------- |
| **存储位置** | 浏览器端（用户电脑）      | 服务器端              |
| **存储内容** | 少量数据（通常只有一个 ID） | 完整的用户状态数据         |
| **安全性**  | 较低（用户可查看、篡改）    | 较高（数据在服务器上，用户看不到） |
| **大小限制** | 约 4KB           | 取决于服务器内存          |
| **生命周期** | 可设置过期时间，长期存在    | 通常关闭浏览器后失效        |

---

### 为什么需要 Session？Cookie 不够用吗？

Cookie 有两个明显的问题：

- **不安全**：Cookie 存在用户电脑上，用户可以查看甚至篡改。如果把"用户角色: 管理员"存在 Cookie 里，用户可能把它改成"管理员"来绕过权限。
- **容量小**：Cookie 最多只能存 4KB 左右，存不了太多数据。

Session 把敏感数据存在服务器上，浏览器端只保留一个无意义的编号（Session ID），即使被人截获，也无法直接获取用户信息。

---

### 一句话总结

- **Cookie** = 会员卡（只写编号，存在你身上）
- **Session** = 档案柜（存完整信息，存在服务器里）
- 两者配合：你出示会员卡（Cookie 里的 Session ID），服务器去档案柜（Session）里查你的信息。
