# HTTP 方法全解：从协议规范到工程实践的完整指南

---

## 一、HTTP 方法总览

### 1.1 核心方法（HTTP/1.1 + 常见扩展）

这些是互联网工程任务组（IETF）在 RFC 7231、RFC 5789 等文档中定义的最基础和最广泛使用的方法。

| 方法          | 描述                                                     | 典型用途                                    |
| ----------- | ------------------------------------------------------ | --------------------------------------- |
| **GET**     | 请求指定的资源。只应读取数据，不应产生副作用。                                | 获取网页、查询数据。                              |
| **HEAD**    | 与 GET 相同，但服务器只返回状态行和头部，不返回消息体。                         | 检查资源是否存在、获取文件大小（Content-Length）或最后修改时间。 |
| **POST**    | 向指定资源提交数据，请求服务器进行处理（如创建或更新）。通常**非幂等**。                 | 提交表单、上传文件、创建新资源（服务器分配 ID）。              |
| **PUT**     | 将请求的有效载荷**完整替换**目标资源。如果资源不存在则创建。是**幂等**的。              | 更新用户资料（需提交完整字段）。                        |
| **PATCH**   | 对资源进行**部分修改**（RFC 5789）。只发送需要变更的字段。通常**非幂等**（取决于补丁格式）。 | 仅修改用户的邮箱，而不提交其他字段。                      |
| **DELETE**  | 删除指定的资源。是**幂等**的。                                      | 删除一篇文章、注销账户。                            |
| **CONNECT** | 将请求连接转换为透明的 TCP/IP 隧道，通常用于通过代理建立 HTTPS 连接。             | 代理服务器建立隧道。                              |
| **OPTIONS** | 返回目标资源支持的 HTTP 方法。常用于跨域（CORS）预检请求。                     | 查询 API 端点支持哪些操作。                        |
| **TRACE**   | 回显客户端收到的请求，主要用于诊断。因存在跨站追踪（XST）安全风险，通常被禁用。              | 调试请求链路。                                 |

### 1.2 WebDAV 扩展方法

WebDAV（Web Distributed Authoring and Versioning，RFC 4918）及其相关扩展（如 DeltaV）为 HTTP 添加了大量用于文件协作、版本控制和属性管理的方法。

|方法|描述|
|---|---|
|**PROPFIND**|检索资源的属性（如作者、修改时间）或目录结构。|
|**PROPPATCH**|修改或删除资源的属性。|
|**MKCOL**|创建新的集合（即目录/文件夹）。|
|**COPY**|将资源或集合复制到另一个 URI。|
|**MOVE**|将资源或集合移动到另一个 URI（类似重命名）。|
|**LOCK**|对资源加锁，防止多人同时编辑产生冲突。|
|**UNLOCK**|释放资源的锁。|
|**REPORT**|查询资源的报告或状态（常用于版本控制，如获取修订历史）。|
|**CHECKOUT**|签出资源以进行编辑（DeltaV 版本控制）。|
|**CHECKIN**|签入资源，创建新版本（DeltaV）。|
|**VERSION-CONTROL**|对资源启用版本控制。|
|**MKWORKSPACE**|创建工作区（Workspace）。|
|**SEARCH**|通过请求体发送查询条件来搜索资源（RFC 5323）。|
|**BIND / UNBIND**|在集合中增加或移除资源的绑定（链接）。|

### 1.3 其他特定用途 / 非标准方法

这些方法并非官方 HTTP/1.1 核心标准，但在特定技术栈或历史规范中被广泛使用。

|方法|描述|使用场景|
|---|---|---|
|**PURGE**|清除指定资源的缓存。|被 Varnish、Fastly、Nginx（proxy_cache_purge）等反向代理和 CDN 广泛支持。|
|**LINK / UNLINK**|建立或断开两个资源之间的链接。|已在 RFC 2068 中定义但后续被废弃，极少使用。|
|**ACL**|修改资源的访问控制列表。|WebDAV ACL（RFC 3744），用于设置权限。|
|**VIEW**|请求资源的特定"视图"。|极少使用，属于早期 HTTP 扩展提案。|

## 二、关键属性速查表

理解以下三个属性，对于构建安全、可缓存和可靠的 API 至关重要：

| 方法          | 安全 (Safe) | 幂等 (Idempotent) | 可缓存 (Cacheable)         |
| ----------- | --------- | --------------- | ----------------------- |
| **GET**     | ✅ 是       | ✅ 是             | ✅ 是                     |
| **HEAD**    | ✅ 是       | ✅ 是             | ✅ 是                     |
| **POST**    | ❌ 否       | ❌ 否             | ⚠️ 仅当响应包含 Freshness 信息时 |
| **PUT**     | ❌ 否       | ✅ 是             | ❌ 否                     |
| **PATCH**   | ❌ 否       | ❌ 通常否           | ❌ 否                     |
| **DELETE**  | ❌ 否       | ✅ 是             | ❌ 否                     |
| **OPTIONS** | ✅ 是       | ✅ 是             | ❌ 否                     |
| **TRACE**   | ✅ 是       | ✅ 是             | ❌ 否                     |
| **CONNECT** | ❌ 否       | ❌ 否             | ❌ 否                     |

### 名词解释

- **安全方法（Safe）**：不修改服务器端资源状态，仅用于读取。GET、HEAD、OPTIONS、TRACE 是安全的。注意：这里的"安全"是**协议语义层面的概念**，仅表示"不改变资源状态"，与日常所说的"防黑客、防窃听"毫无关系——这是开发者最容易混淆的地方。
- **幂等方法（Idempotent）**：客户端发起一次或多次相同请求，对服务器资源状态产生的**最终效果**与仅发起一次请求完全相同。例如 PUT 和 DELETE 是幂等的——即使资源已被删除，再次 DELETE 也不会造成额外的状态变化（尽管服务器可能返回 404，但"资源不存在"这个状态本身是稳定的）。
- **可缓存（Cacheable）**：响应可以被客户端或中间代理缓存，以减少服务器负载和网络带宽消耗。
