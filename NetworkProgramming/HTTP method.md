## 核心方法（HTTP/1.1 + 常见扩展）

这些是互联网工程任务组（IETF）在 RFC 7231、RFC 5789 等文档中定义的最基础和最广泛使用的方法。

| 方法           | 描述                                             | 典型用途                                    |
| ------------ | ---------------------------------------------- | --------------------------------------- |
| **GET**​     | 请求指定的资源。只应读取数据，不应产生副作用。                        | 获取网页、查询数据。                              |
| **HEAD**​    | 与 GET 相同，但服务器只返回状态行和头部，不返回消息体。                 | 检查资源是否存在、获取文件大小（Content-Length）或最后修改时间。 |
| **POST**​    | 向指定资源提交数据，请求服务器进行处理（如创建或更新）。通常**非幂等**。         | 提交表单、上传文件、创建新资源（服务器分配ID）。               |
| **PUT**​     | 将请求的有效载荷**完整替换**目标资源。如果资源不存在则创建。是**幂等**的。      | 更新用户资料（需提交完整字段）。                        |
| **PATCH**​   | 对资源进行**部分修改**（RFC 5789）。只发送需要变更的字段。通常**非幂等**。  | 仅修改用户的邮箱，而不提交其他字段。                      |
| **DELETE**​  | 删除指定的资源。是**幂等**的（即使已删除，再次删除也不报错或返回404）。        | 删除一篇文章、注销账户。                            |
| **CONNECT**​ | 将请求连接转换为透明的 TCP/IP 隧道，通常用于 SSL 通过代理的 HTTPS 连接。 | 代理服务器建立隧道。                              |
| **OPTIONS**​ | 返回目标资源支持的 HTTP 方法。常用于跨域（CORS）预检请求。             | 查询 API 端点支持哪些操作。                        |
| **TRACE**​   | 回显客户端请求，主要用于诊断。因存在跨站追踪（XST）安全风险，通常被禁用。         | 调试请求链路。                                 |
